# HU-015 · Registro de máquinas y QR

## Alcance implementado

El administrador registra una máquina con código, nombre, número de serie, grupo muscular, sede activa y estado inicial. El backend guarda los datos en la colección MongoDB `maquinas`. Código y serie se normalizan a mayúsculas y tienen restricciones de unicidad; los errores señalan el campo duplicado. Una sede inactiva o inexistente impide el alta.

Al registrar la máquina se crea un identificador QR único e inmutable. El QR descargable es un archivo SVG apto para imprimir. Su contenido es `pikafit:maquina:<token>`; el token se resuelve mediante la API para identificar la máquina, sin exponer su identificador interno en la impresión.

## Archivos principales

- `Administracion/back/src/maquina/models.py`: colección, campos y estados.
- `Administracion/back/src/maquina/services.py`: sede activa, duplicados y registro.
- `Administracion/back/src/maquina/qr.py`: contenido y generación del SVG.
- `Administracion/back/src/maquina/views.py`: endpoints protegidos.
- `Administracion/front-web/src/MaquinasApp.tsx`: formulario, listado y descarga.

## API

| Operación | Ruta | Acceso |
| --- | --- | --- |
| Listar y registrar | `GET/POST /api/v1/maquinas/` | Administrador del gimnasio |
| Consultar una máquina | `GET /api/v1/maquinas/<id>/` | Administrador del gimnasio |
| Descargar el QR | `GET /api/v1/maquinas/<id>/qr/` | Administrador del gimnasio |
| Identificar un QR escaneado | `GET /api/v1/maquinas/identificar/<token>/` | Sesión autenticada de Administración |

Ejemplo de alta:

```json
{
  "codigo": "MAQ-001",
  "nombre": "Prensa de piernas",
  "numero_serie": "SER-2026-001",
  "grupo_muscular": "Piernas",
  "sede_id": "<id de una sede activa>",
  "estado": "operativa"
}
```

Estados admitidos: `operativa`, `mantenimiento`, `fuera_servicio`.

## Puesta en marcha y verificación pendiente

Instalar `Administracion/back/requirements.txt`, aplicar las migraciones de Django contra MongoDB y ejecutar el backend. En la interfaz de Administración, abrir **Máquinas y QR** con una sesión de administrador. Seleccionar una sede activa, registrar la máquina y descargar el SVG desde el listado.

La compilación de React y la comprobación de configuración de Django pasan. Quedan pendientes las pruebas funcionales de registro, campos faltantes, código y serie duplicados, sede inactiva, escaneo del QR e integración del inicio de sesión en la interfaz. El endpoint de identificación usa la autenticación Django de Administración; la conexión del lector móvil de Usuario corresponde a una integración posterior.
